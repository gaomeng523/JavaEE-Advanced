## 1. 前言与技术栈

## 2. 项目介绍

一个 SSM 框架的简易博客系统，共 5 个页面：

| 页面 | 文件 | 是否需要登录 |
| --- | --- | --- |
| 用户登录页 | `blog_login.html` | 否 |
| 博客列表页 | `blog_list.html` | 否（可匿名浏览） |
| 博客详情页 | `blog_detail.html` | 否（可匿名浏览） |
| 博客发表页 | `blog_edit.html` | **是** |
| 博客编辑页 | `blog_update.html` | **是** |

功能流程：**用户登录成功后可以查看所有人的博客**；点击「查看全文」进入详情页；**如果该博客作者是当前登录用户**，可以修改、删除，以及发表新博客。

## 4. 公共模块

公共模块的目标：**让 Controller 只写业务，不写「格式转换 / 异常兜底 / 状态码」这些重复代码**。

### 4.1 统一响应结果 Result

后端所有接口最终都返回一个统一结构：

```json
{ "code": 200, "errMsg": null, "data": { /* 业务数据 */ } }
```

**状态码枚举**：

```java
package com.example.springblogdemo.common.enums;

import lombok.AllArgsConstructor;
import lombok.Getter;

@AllArgsConstructor
public enum ResultCodeEnum {
    SUCCESS(200),
    FAIL(-1);

    @Getter
    private int code;
}
```

**Result 泛型类**：

```java
package com.example.springblogdemo.pojo.response;

import com.example.springblogdemo.common.enums.ResultCodeEnum;
import lombok.Data;

@Data
public class Result<T> {
    private int code;
    private String errMsg;
    private T data;

    public static <T> Result<T> success(T data) {
        Result<T> result = new Result<>();
        result.setCode(ResultCodeEnum.SUCCESS.getCode());
        result.setData(data);
        return result;
    }

    public static <T> Result<T> fail(String errMsg) {
        Result<T> result = new Result<>();
        result.setCode(ResultCodeEnum.FAIL.getCode());
        result.setErrMsg(errMsg);
        return result;
    }
}
```

> **易错点**：不要写成裸类型 `Result result = new Result();`，编译期会有「未检查的转换」警告。

### 4.2 自定义业务异常 BlogException

业务里的错误（用户不存在、密码错误、越权访问）不该走 HTTP 500，应该走「HTTP 200 + code=-1」的形式返回给前端，方便前端做业务判断。

```java
package com.example.springblogdemo.common.exception;

import lombok.Data;

@Data
public class BlogException extends RuntimeException {
    private Integer code;
    private String message;

    public BlogException(Integer code, String message) {
        this.code = code;
        this.message = message;
    }

    public BlogException(String message) {
        this.message = message;
    }
}
```

### 4.3 全局异常处理 ExceptionAdvice

用 `@RestControllerAdvice` 把所有 Controller 抛出的异常统一翻译成 `Result` 结构。

```java
package com.example.springblogdemo.common.advice;

import com.example.springblogdemo.common.exception.BlogException;
import com.example.springblogdemo.pojo.response.Result;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.method.annotation.HandlerMethodValidationException;

@Slf4j
@RestControllerAdvice
public class ExceptionAdvice {

    /** 业务异常：可预期错误，warn 级别，不打堆栈 */
    @ExceptionHandler(BlogException.class)
    public Result handler(BlogException e) {
        log.warn("业务异常：{}", e.getMessage());
        return Result.fail(e.getMessage());
    }

    /** 方法参数校验失败（@NotNull 之类挂在方法参数上的） */
    @ResponseStatus(code = HttpStatus.BAD_REQUEST)
    @ExceptionHandler(HandlerMethodValidationException.class)
    public Result handler(HandlerMethodValidationException e) {
        log.warn("参数校验失败：{}", e.getMessage());
        return Result.fail("参数不合法");
    }

    /** @RequestBody 对象内部字段校验失败 */
    @ResponseStatus(code = HttpStatus.BAD_REQUEST)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result handler(MethodArgumentNotValidException e) {
        FieldError fieldError = e.getBindingResult().getFieldError();
        String message = fieldError == null ? "参数不合法" : fieldError.getDefaultMessage();
        log.warn("参数校验失败：{}", message);
        return Result.fail(message);
    }

    /** 兜底：其他所有异常。消息做脱敏，避免暴露 SQL / 表名 */
    @ExceptionHandler(Exception.class)
    public Result handler(Exception e) {
        log.error("系统异常", e);
        return Result.fail("系统开小差了，请稍后重试");
    }
}
```

三个异常处理器分工：

| 场景 | 抛出的异常 | 处理方法 |
| --- | --- | --- |
| Service 主动 `throw new BlogException(...)` | `BlogException` | 第 1 个 |
| Controller 方法参数 `@NotNull Integer blogId`，前端没传 | `HandlerMethodValidationException` | 第 2 个 |
| Controller `@RequestBody @Validated XxxRequest` 字段约束失败 | `MethodArgumentNotValidException` | 第 3 个 |
| 数据库连不上、空指针、其他 | `Exception` | 第 4 个兜底 |

### 4.4 统一响应包装 ResponseAdvice

用 `ResponseBodyAdvice` 把 Controller 的返回值自动包成 `Result`，这样 Controller 里就直接 `return userInfo;` 就行，不用每次手动 `Result.success(...)`。

```java
package com.example.springblogdemo.common.advice;

import com.example.springblogdemo.pojo.response.Result;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.SneakyThrows;
import org.springframework.core.MethodParameter;
import org.springframework.http.MediaType;
import org.springframework.http.server.ServerHttpRequest;
import org.springframework.http.server.ServerHttpResponse;
import org.springframework.lang.Nullable;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.servlet.mvc.method.annotation.ResponseBodyAdvice;

@ControllerAdvice
public class ResponseAdvice implements ResponseBodyAdvice<Object> {

    private final ObjectMapper objectMapper;

    public ResponseAdvice(ObjectMapper objectMapper) {
        this.objectMapper = objectMapper;
    }

    /** 排除文档接口，否则 Swagger 页面会因为多套一层 Result 而渲染不出来 */
    @Override
    public boolean supports(MethodParameter returnType, Class converterType) {
        String className = returnType.getDeclaringClass().getName();
        return !className.contains("springfox")
                && !className.contains("springdoc")
                && !className.contains("Swagger");
    }

    @SneakyThrows
    @Nullable
    @Override
    public Object beforeBodyWrite(@Nullable Object body,
                                  MethodParameter returnType,
                                  MediaType selectedContentType,
                                  Class selectedConverterType,
                                  ServerHttpRequest request,
                                  ServerHttpResponse response) {
        // ① 已经是 Result（异常处理器返回的）→ 原样返回，避免套两层
        if (body instanceof Result<?>) {
            return body;
        }
        // ② String 类型必须手动序列化成 JSON 字符串。
        //   Spring 给 String 用的是 StringHttpMessageConverter，
        //   直接返回 Result 对象它没法转换，会抛 ClassCastException。
        if (body instanceof String) {
            return objectMapper.writeValueAsString(Result.success(body));
        }
        // ③ 其余对象交给 Jackson 正常序列化
        return Result.success(body);
    }
}
```

### 4.6 POJO 转换工具 BeanTransfer

把散落各处的 `BeanUtils.copyProperties` 统一收口：

```java
package com.example.springblogdemo.common.utils;

import com.example.springblogdemo.pojo.dataobject.BlogInfo;
import com.example.springblogdemo.pojo.dataobject.UserInfo;
import com.example.springblogdemo.pojo.request.AddBlogRequest;
import com.example.springblogdemo.pojo.request.UpdateBlogRequest;
import com.example.springblogdemo.pojo.response.BlogInfoResponse;
import com.example.springblogdemo.pojo.response.UserInfoResponse;
import org.springframework.beans.BeanUtils;

public class BeanTransfer {

    private BeanTransfer() { /* 工具类禁止实例化 */ }

    public static BlogInfoResponse trans(BlogInfo blogInfo) {
        if (blogInfo == null) return null;
        BlogInfoResponse resp = new BlogInfoResponse();
        BeanUtils.copyProperties(blogInfo, resp);
        return resp;
    }

    public static UserInfoResponse trans(UserInfo userInfo) {
        if (userInfo == null) return null;
        UserInfoResponse resp = new UserInfoResponse();
        BeanUtils.copyProperties(userInfo, resp);
        return resp;
    }

    /** 新增请求 → 实体。userId 由 Service 从当前登录人补，不接收前端传参 */
    public static BlogInfo trans(AddBlogRequest req) {
        if (req == null) return null;
        BlogInfo blogInfo = new BlogInfo();
        BeanUtils.copyProperties(req, blogInfo);
        return blogInfo;
    }

    /** 更新请求 → 实体。null 字段不会被 updateById 更新（MP 动态 SQL 特性） */
    public static BlogInfo trans(UpdateBlogRequest req) {
        if (req == null) return null;
        BlogInfo blogInfo = new BlogInfo();
        BeanUtils.copyProperties(req, blogInfo);
        return blogInfo;
    }
}
```

> **易错点**：`BeanUtils.copyProperties(source, target)` 是**按属性名拷贝**，字段名对不上就不会拷过去。所以 DO / DTO / VO 的字段命名要保持一致，或者显式手写 `set`。

## 5. 实体类与 Mapper

### 5.1 UserInfo / BlogInfo（MyBatis-Plus 实体）

```java
package com.example.springblogdemo.pojo.dataobject;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;
import java.util.Date;

@Data
public class UserInfo {
    @TableId(value = "id", type = IdType.AUTO)
    private Integer id;
    private String userName;
    private String password;
    private String githubUrl;

    /** 逻辑删除：0=未删，1=已删。MP 会自动给 select/update 拼 delete_flag=0，给 delete 变成 update */
    @TableLogic(value = "0", delval = "1")
    private Integer deleteFlag;

    /** 插入时自动填充 */
    @TableField(fill = FieldFill.INSERT)
    private Date createTime;

    /** 插入和更新时都自动填充 */
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private Date updateTime;
}
```

```java
@Data
public class BlogInfo {
    @TableId(value = "id", type = IdType.AUTO)
    private Integer id;
    private String title;
    private String content;
    private Integer userId;

    @TableLogic(value = "0", delval = "1")
    private Integer deleteFlag;

    @TableField(fill = FieldFill.INSERT)
    private Date createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private Date updateTime;
}
```

三个 MP 注解的作用：

| 注解 | 作用 |
| --- | --- |
| `@TableId(type = IdType.AUTO)` | 主键使用数据库自增 |
| `@TableLogic(value="0", delval="1")` | 逻辑删除。`deleteById` 自动变成 `UPDATE ... SET delete_flag=1`；所有 select / update 自动追加 `WHERE delete_flag=0` |
| `@TableField(fill=...)` | 字段自动填充，配合 `MyMetaObjectHandler` 使用 |

### 5.2 MyMetaObjectHandler 自动填充

```java
package com.example.springblogdemo.config;

import com.baomidou.mybatisplus.core.handlers.MetaObjectHandler;
import lombok.extern.slf4j.Slf4j;
import org.apache.ibatis.reflection.MetaObject;
import org.springframework.stereotype.Component;
import java.util.Date;

@Slf4j
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    /** 插入时：createTime 和 updateTime 都填当前时间 */
    @Override
    public void insertFill(MetaObject metaObject) {
        Date now = new Date();
        // strictInsertFill 只在字段为 null 时填充，避免覆盖业务里手动设置的值
        this.strictInsertFill(metaObject, "createTime", Date.class, now);
        this.strictInsertFill(metaObject, "updateTime", Date.class, now);
    }

    /** 更新时：只刷新 updateTime，createTime 保持不变 */
    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", Date.class, new Date());
    }
}
```

有了这个组件，Service 里 `blogMapper.insert(blogInfo)` 时**不用再手动 setCreateTime**，MP 会自动填。

## 7. 【重点】JWT 登录鉴权

### 7.1 为什么不用 Session

传统思路：登录成功后服务器创建 Session，把 sessionId 通过 Cookie 下发给浏览器，后续请求浏览器自动带 Cookie，服务器根据 sessionId 找回 Session 判断登录态。

**问题**：集群环境下 Session 存在单机内存里，负载均衡把请求转到另一台服务器时，那台机器上没有这个 Session，就会认为用户没登录。

**解决方案对比**：

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| Session 复制 | 每台机器都有全量 Session | 网络开销大、内存浪费 |
| Session 集中存储（Redis） | 解决复制问题 | 依赖 Redis、增加运维成本 |
| **令牌（Token）** | **服务器无状态、天然支持集群** | **需要自己实现生成 / 传递 / 校验** |

企业开发中最常用的就是令牌方案，而 JWT 是令牌的一种标准实现。

### 7.2 JWT 组成

JWT 全称 **JSON Web Token**，官网 <https://jwt.io/>，本质是一个字符串，格式：`aaaaa.bbbbb.ccccc`（点号分隔的三段）。

| 部分 | 内容 | 编码方式 |
| --- | --- | --- |
| **Header（头部）** | 令牌类型（JWT）+ 签名算法（HS256） | Base64Url |
| **Payload（负载）** | 自定义字段（userId、username）+ 标准字段（exp 过期时间、iat 签发时间） | Base64Url |
| **Signature（签名）** | `HMACSHA256(base64(header) + "." + base64(payload), secret)` | 二进制 → Base64Url |

> **重要认知**：Base64 是**编码**不是**加密**，任何人都可以把 Payload 解出来看到里面的内容。JWT 之所以安全，是因为**签名不可伪造**——只要改动 Header 或 Payload 里任何一个字符，Signature 就对不上，服务器就会拒绝。
>
> 类比身份证：身份证上的信息谁都能看到，但**不能篡改**，这才是它作为身份凭证的核心。

### 7.3 生成 JWT 密钥

JWT 密钥有长度和熵的要求，**不要手写一个字符串**，用官方 API 生成：

```java
@Test

    Key key = Keys.secretKeyFor(SignatureAlgorithm.HS256);
    String secretString = Encoders.BASE64.encode(key.getEncoded());
    System.out.println(secretString);
    // 输出示例：+JEq/o2bYDEtaECkxKCeAt0i3yA0IPUlV2rxFVGS+v4=

```

### 7.4 JwtUtil 组件化设计

课件里的 `JWTUtils` 是**静态工具类**、密钥硬编码。我改成了 **Spring 组件**、密钥通过 `@Value` 从 yml 注入，理由：

| 维度 | 静态工具类 | Spring 组件（本项目采用） |
| --- | --- | --- |
| 密钥管理 | 硬编码在源码里 | yml / 环境变量 / 配置中心 |
| 单元测试 | 难 mock | 可以注入 mock 实例 |
| 修改密钥 | 改代码重新编译 | 改配置重启即可 |
| 使用姿势 | `JwtUtil.genJwt(...)` | `@Autowired JwtUtil` 后 `jwtUtil.genJwt(...)` |

```java
package com.example.springblogdemo.common.utils;

import com.example.springblogdemo.common.constants.Constant;
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.JwtParser;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.io.Decoders;
import io.jsonwebtoken.security.Keys;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import java.security.Key;
import java.util.Date;
import java.util.Map;

@Slf4j
@Component
public class JwtUtil {

    /** 过期时长：7 天。生产环境要根据业务权衡（越长越方便、越短越安全） */
    public static final long EXPIRATION_TIME = 7 * 24 * 60 * 60 * 1000L;

    private final Key key;

    /** 构造器注入：密钥从 application.yml 的 jwt.secret 读取 */
    public JwtUtil(@Value("${jwt.secret}") String secretString) {
        this.key = Keys.hmacShaKeyFor(Decoders.BASE64.decode(secretString));
    }

    /**
     * 生成 token
     * @param claim 自定义载荷，通常放 id 和 username
     */
    public String genJwt(Map<String, Object> claim) {
        return Jwts.builder()
                .setClaims(claim)                                                   // 载荷
                .setIssuedAt(new Date())                                            // 签发时间
                .setExpiration(new Date(System.currentTimeMillis() + EXPIRATION_TIME)) // 过期时间
                .signWith(key)                                                      // 签名
                .compact();
    }

    /**
     * 解析 token
     * 解析失败（签名不对 / 已过期 / 格式错误）统一返回 null，由调用方决定怎么处理
     */
    public Claims parseJwt(String token) {
        JwtParser parser = Jwts.parserBuilder().setSigningKey(key).build();
        try {
            return parser.parseClaimsJws(token).getBody();
        } catch (Exception e) {
            // 只记录失败原因，不要把完整 token 打进日志，避免 token 泄露
            log.warn("token 解析失败：{}", e.getMessage());
            return null;
        }
    }

    /** 从 token 中取用户 id */
    public Integer getUserId(String token) {
        Claims claims = parseJwt(token);
        if (claims == null) return null;
        Object id = claims.get(Constant.JWT_CLAIM_ID);
        return id == null ? null : Integer.valueOf(id.toString());
    }
}
```

### 7.9 localStorage 三个 API

| 操作 | 语法 |
| --- | --- |
| 存 | `localStorage.setItem("userToken", token)` |
| 读 | `localStorage.getItem("userToken")` |
| 删 | `localStorage.removeItem("userToken")` |

**为什么用 localStorage 而不是 Cookie**：

- Cookie 会被浏览器自动带到同域所有请求，包括静态资源，浪费带宽；
- Cookie 有 4KB 大小限制，JWT 有可能超过；
- localStorage 只在 JS 主动读取时才会带上，更可控；
- 缺点：容易被 XSS 偷（所以 §12.3 要做 HTML 转义）。

## 8. 【重点】LoginInterceptor 登录拦截

### 8.1 拦截器原理

SpringMVC 的 `HandlerInterceptor` 有三个方法：

| 方法 | 时机 | 返回值意义 |
| --- | --- | --- |
| `preHandle` | Controller 方法执行**前** | `true` 放行，`false` 拦截 |
| `postHandle` | Controller 方法执行**后**、视图渲染**前** | 无 |
| `afterCompletion` | 视图渲染**后**（整个请求完成） | 无 |

登录校验只需要 `preHandle`：token 合法就放行，不合法就返回 401。

### 8.2 LoginInterceptor 实现

```java
package com.example.springblogdemo.common.interceptor;

import com.example.springblogdemo.common.constants.Constant;
import com.example.springblogdemo.common.utils.JwtUtil;
import io.jsonwebtoken.Claims;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;
import org.springframework.util.StringUtils;
import org.springframework.web.servlet.HandlerInterceptor;

@Slf4j
@Component
public class LoginInterceptor implements HandlerInterceptor {

    private final JwtUtil jwtUtil;

    // JwtUtil 是 Spring 组件，通过构造器注入拿实例，不能静态调用
    public LoginInterceptor(JwtUtil jwtUtil) {
        this.jwtUtil = jwtUtil;
    }

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) {
        // ① 从请求头取 token
        String userToken = request.getHeader(Constant.USER_TOKEN_HEADER);

        // ② token 为空直接拒绝
        //    注意这里不能继续往下调 parseJwt，否则会刷无意义的错误日志
        if (!StringUtils.hasText(userToken)) {
            log.warn("请求被拦截：未携带 token，uri={}", request.getRequestURI());
            response.setStatus(401);
            return false;
        }

        // ③ 解析 token（签名 / 过期 / 格式任一失败都会返回 null）
        Claims claims = jwtUtil.parseJwt(userToken);
        if (claims == null) {
            log.warn("请求被拦截：token 解析失败，uri={}", request.getRequestURI());
            response.setStatus(401);
            return false;
        }

        // ④ 从载荷取 userId，存入 request 域
        //    JWT 里的数字反序列化后可能是 Integer 也可能是 Long，
        //    统一转 Integer 更稳妥（先 toString 再 valueOf）
        Object idObj = claims.get(Constant.JWT_CLAIM_ID);
        if (idObj == null) {
            log.warn("请求被拦截：token 中缺少用户 id，uri={}", request.getRequestURI());
            response.setStatus(401);
            return false;
        }
        Integer userId = Integer.valueOf(idObj.toString());
        request.setAttribute(Constant.CURRENT_USER_ID, userId);

        // ⑤ 成功放行也打一行日志。
        //    否则「登录状态下正常操作」在控制台完全静默，
        //    很容易被误判成「拦截器没被调用」
        log.info("登录校验通过，userId:{}, uri:{}, method:{}",
                userId, request.getRequestURI(), request.getMethod());

        return true;
    }
}
```

### 8.3 WebConfig 注册拦截器

```java
package com.example.springblogdemo.config;

import com.example.springblogdemo.common.interceptor.LogInterceptor;
import com.example.springblogdemo.common.interceptor.LoginInterceptor;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    private final LoginInterceptor loginInterceptor;
    private final LogInterceptor logInterceptor;

    public WebConfig(LoginInterceptor loginInterceptor, LogInterceptor logInterceptor) {
        this.loginInterceptor = loginInterceptor;
        this.logInterceptor = logInterceptor;
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        // ① 观测拦截器：拦全部路径，只打日志、不做鉴权。
        //    让你在控制台能直观看到「拦截器机制在工作」
        registry.addInterceptor(logInterceptor).addPathPatterns("/**");

        // ② 登录拦截器：真正的鉴权，只拦需要登录的写接口
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns(
                        "/blog/addBlog",        // 新增博客
                        "/blog/updateBlog",     // 修改博客
                        "/blog/deleteBlog",     // 删除博客
                        "/user/getUserInfo"     // 查「当前登录人」信息
                )
                // 登录接口本身不能被拦截
                .excludePathPatterns("/user/login");
    }
}
```

### 8.4 拦截路径的选型原则 ★

**这是本节最重要的一个决策**：

> **新增接口时的判断标准**：这个接口会**按「当前登录人」返回数据**、或**修改数据**吗？
>
> - **会** → 加进 `addPathPatterns`；
> - **只是读取公开数据** → 不加。

按这个原则，本项目的接口分类：

| 接口 | 是否拦截 | 原因 |
| --- | --- | --- |
| `POST /user/login` | **排除** | 登录本身不能要求已登录 |
| `GET /user/getUserInfo` | **拦截** | 查的是「当前登录人」的信息，必须登录 |
| `GET /user/getAuthorInfo` | 不拦截 | 查博客作者的信息，是公开数据，匿名访客也要能看 |
| `GET /blog/getList` | 不拦截 | 博客列表是公开的，匿名可浏览 |
| `GET /blog/getBlogDetail` | 不拦截 | 博客详情是公开的，匿名可浏览 |
| `GET /blog/countByUser` | 不拦截 | 统计任意作者的文章数，与「当前登录人」无关 |
| `POST /blog/addBlog` | **拦截** | 写操作 |
| `POST /blog/updateBlog` | **拦截** | 写操作 |
| `POST /blog/deleteBlog` | **拦截** | 写操作 |

> **反面教材**：如果直接把 `/blog/**` 全拦了，未登录用户连首页都打不开。博客系统本来就是「读公开、写受控」的典型场景。

### 8.5 request 域传 userId + Controller 用 @RequestAttribute 取

拦截器解析出 userId 后**存进 request 域**，Controller 用 `@RequestAttribute` 取出来用，**不接收前端传的 userId**。

```java
@PostMapping("addBlog")
public Boolean addBlog(@Validated @RequestBody AddBlogRequest req,
                       @RequestAttribute(name = Constant.CURRENT_USER_ID, required = false) Integer userId) {
    log.info("新增博客，userId:{}, title:{}", userId, req.getTitle());
    return blogService.addBlog(req, requireLogin(userId));
}

/**
 * 兜底校验：确保当前请求确实是登录态
 * 正常情况下拦截器已经拦住了未登录请求，userId 一定不为空。
 * 但万一将来新增接口时漏配了拦截路径，这里能及时挡住。
 * 属于「防御性编程」——依赖链路上的安全措施不要单点。
 */
private Integer requireLogin(Integer userId) {
    if (userId == null) {
        log.warn("未登录用户尝试执行写操作");
        throw new BlogException("请先登录");
    }
    return userId;
}
```

**为什么不能信任前端传的 userId**：如果 `AddBlogRequest` 里包含 `userId` 字段，攻击者用 Postman 把 userId 改成别人的 id，就能伪造成别人发博客。**服务端解析的 token 才是唯一可信来源**。

### 8.6 前端 ajaxSend 动态携带 token

在 `common.js` 中统一配置，每个 ajax 请求都会自动带 `User-Token`：

```javascript
/**
 * 【关键】必须用 beforeSend / ajaxSend 每次请求时「现读」localStorage，
 * 绝对不能写成 ajaxSetup({ headers: { "User-Token": localStorage.getItem(...) } })。
 *
 * 原因：ajaxSetup 只在页面加载时执行一次，headers 里的值是那一刻算出来的静态字符串。
 * 一旦写死，就会出现两种故障：
 *   1. 登录后跳转前的请求，仍带着登录前的空 token；
 *   2. 401 处理里删掉 localStorage 后，header 的值还是旧的，永远清不干净。
 */
$(document).ajaxSend(function (event, xhr) {
    var token = localStorage.getItem("userToken");
    if (token) {
        // 只在确实有 token 时才带上这个头，避免发送无意义的空 header
        xhr.setRequestHeader("User-Token", token);
    }
});
```

### 8.8 LogInterceptor 观测拦截器

这是一个**只打日志、不做鉴权**的拦截器，用于排查「拦截器到底有没有被调用」：

```java
@Slf4j

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) {
        log.info("[拦截链路] {} {} 已进入拦截器",
                request.getMethod(), request.getRequestURI());
        return true;   // 只观测，永远放行
    }
}
```

**为什么单独一个类而不是在 LoginInterceptor 里加日志**：LoginInterceptor 只挂 4 个写接口，它天然无法证明「全局拦截链路是通的」。LogInterceptor 拦 `/**`（全部路径），只要任意请求进来就打日志，能直接证明「Spring MVC 的拦截器机制本身在工作」。

**排查完建议关掉**：它会对所有请求（包括 css/js/html 静态资源）打日志，正式使用时日志会比较吵。把 `WebConfig` 里注册它的那行注释掉，或把 `log.info` 降级为 `log.debug`。

```java
@Override
```

```java
    BlogInfo exist = getBlogInfo(req.getId());
    if (exist == null) {
        throw new BlogException("博客不存在");
    }

    if (!StringUtils.hasText(blogInfo.getTitle())
            && !StringUtils.hasText(blogInfo.getContent())) {
        return true;

    // updateById 只更新非 null 字段（MP 动态 SQL 特性）
    blogMapper.updateById(blogInfo);

    // ★ 不能判断 rows != 1 就报错。
    //   MySQL 在「新值和旧值完全相同」时受影响行数是 0，但这不是失败
    return true;
```

## 11. 【重点】密码加密：MD5 加盐

### 11.1 为什么要加密

数据库里如果存明文密码，一旦拖库，用户密码直接泄露。用户在多个平台复用密码是常态，一次泄露可能导致连锁反应。

### 11.2 密码算法三大类

| 类别 | 特点 | 常见算法 | 能否解密 |
| --- | --- | --- | --- |
| **对称加密** | 加密 / 解密密钥相同 | AES、DES、3DES、RC4 | 能 |
| **非对称加密** | 公钥加密、私钥解密 | RSA、DSA、ECDSA、ECC | 能 |
| **摘要算法（哈希）** | 任意长度 → 固定长度，不可逆 | **MD5**、SHA-1/256、CRC32 | **不能** |

密码存储用**摘要算法**——不需要解密，只需要「验证」。

### 11.3 单纯 MD5 的问题：彩虹表

MD5 是确定性函数：相同输入永远得到相同输出。攻击者可以预先算好常见密码的 MD5 值做成「彩虹表」，拖库后直接反查：

| 明文 | MD5 |
| --- | --- |
| `123456` | `e10adc3949ba59abbe56e057f20f883e` |
| `password` | `5f4dcc3b5aa765d61d8327deb882cf99` |
| `admin` | `21232f297a57a5a743894a0e4a801fc3` |

只要数据库里的密文出现在彩虹表中，密码就秒破。

### 11.4 解决方案：加盐（Salt）

**思路**：给每个密码拼接一段**随机字符串**（盐），再一起做 MD5。同一个密码，因为盐不同，密文也不同。

```
用户 A 密码 "123456"，盐 "abc..."  →  MD5("123456abc...") = "xxx..."
用户 B 密码 "123456"，盐 "xyz..."  →  MD5("123456xyz...") = "yyy..."
```

彩虹表失效——攻击者不可能预先算出「所有盐 × 所有密码」的组合。

### 11.5 存储格式设计

**核心问题**：盐是随机的，验证时怎么知道当初用了什么盐？

**答案**：**把盐和密文一起存到数据库**。

本项目采用的存储格式：

```
┌──────────────────────────────────────┬──────────────────────────────────────┐
│   前 32 位：MD5(密码 + 盐) 的十六进制   │   后 32 位：盐（UUID 去横线）           │
└──────────────────────────────────────┴──────────────────────────────────────┘
                     总长度固定 64 位十六进制字符
```

**为什么用 UUID 做盐**：`UUID.randomUUID().toString().replace("-","")` 天然是 32 位十六进制字符，长度固定、熵足够、不用自己写随机数生成器。

### 11.6 Md5Util 完整实现

```java
package com.example.springblogdemo.common.utils;

import lombok.extern.slf4j.Slf4j;
import org.springframework.util.DigestUtils;
import org.springframework.util.StringUtils;

import java.nio.charset.StandardCharsets;
import java.util.UUID;

/**
 * MD5 加盐加密工具
 *
 * 存储格式：finalPassword(32位) + salt(32位)，总长度固定 64 位。
 * 前 32 位是「密码 + 盐」的 MD5 值，后 32 位是盐本身。
 *
 * 关于安全性：MD5 加盐足以抵挡彩虹表，但 MD5 计算速度极快，
 * 面对暴力破解依然偏弱。学习阶段够用，生产环境请换 BCrypt / Argon2。
 */
@Slf4j
public class Md5Util {

    /** MD5 十六进制字符串的长度 */
    private static final int MD5_LENGTH = 32;

    /** 加盐后存储的总长度：MD5(32) + salt(32) */
    private static final int STORED_LENGTH = MD5_LENGTH * 2;

    /**
     * 对明文密码加盐加密
     *
     * 每次调用都会生成一个全新的随机盐，因此同一个密码两次加密的结果必然不同——
     * 这正是加盐的意义：攻击者无法通过「密文相同」判断两个用户密码是否一致。
     *
     * @param password 明文密码
     * @return 32 位 MD5 值 + 32 位盐，共 64 位
     */
    public static String encrypt(String password) {
        // UUID 去掉横线后正好是 32 位十六进制字符，天然适合当盐
        String salt = UUID.randomUUID().toString().replace("-", "");
        // 把盐拼在密码后面一起做摘要，这样相同密码也会得到不同结果
        String finalPassword = DigestUtils.md5DigestAsHex(
                (password + salt).getBytes(StandardCharsets.UTF_8));
        // 盐必须和密文一起存下来，否则后续无法校验
        return finalPassword + salt;
    }

    /**
     * 校验明文密码是否与数据库中存储的密文匹配
     *
     * @param inputPassword  用户本次输入的明文密码
     * @param storedPassword 数据库中存储的 64 位密文（MD5 + salt）
     * @return 匹配返回 true，否则 false
     */
    public static Boolean verify(String inputPassword, String storedPassword) {
        if (!StringUtils.hasText(inputPassword) || !StringUtils.hasText(storedPassword)) {
            log.warn("密码校验失败：输入密码或数据库密码为空");
            return false;
        }
        // 长度不符说明数据有问题（比如历史数据没加盐），直接判定失败，避免 substring 越界
        if (storedPassword.length() != STORED_LENGTH) {
            log.warn("密码校验失败：密文长度不是 {} 位，实际 {} 位",
                    STORED_LENGTH, storedPassword.length());
            return false;
        }

        // ★ 存储格式是「密文在前、盐在后」
        //   前 32 位是已存好的摘要，后 32 位才是盐
        String finalPassword = storedPassword.substring(0, MD5_LENGTH);
        String salt = storedPassword.substring(MD5_LENGTH);

        // 用取出的盐重新计算一遍摘要，与数据库里的摘要比对
        // 这里必须是 (输入的密码 + 盐)，顺序要和 encrypt 保持一致
        String computedPassword = DigestUtils.md5DigestAsHex(
                (inputPassword + salt).getBytes(StandardCharsets.UTF_8));

        return computedPassword.equals(finalPassword);
    }
}
```

### 11.7 加密 / 校验流程对比

**注册 / 初始化时的加密流程**：

```
明文 "123456"
    ↓
生成随机盐 salt = UUID.randomUUID().replace("-", "")    → 例如 "a1b2c3d4e5f6..."（32位）
    ↓
拼接：password + salt = "123456a1b2c3d4e5f6..."
    ↓
MD5 摘要：DigestUtils.md5DigestAsHex(...)              → 例如 "e2377426880545d287b97ee294fc30ea"（32位）
    ↓
拼接存储：finalPassword + salt                          → "e2377426880545d287b97ee294fc30ea" + "a1b2c3d4e5f6..."
    ↓
写入数据库 password 字段（64 位）
```

**登录时的校验流程**：

```
用户输入明文 "123456"
    ↓
从数据库读出 storedPassword（64 位）
    ↓
拆分：finalPassword = storedPassword.substring(0, 32)    → 前 32 位是密文
      salt          = storedPassword.substring(32)       → 后 32 位是盐
    ↓
用取出的盐 + 用户输入的密码重新算：
   computed = MD5(inputPassword + salt)
    ↓
比较：computed.equals(finalPassword)
    ├─ 相同 → 密码正确
    └─ 不同 → 密码错误
```

### 11.8 单元测试验证

```java

    System.out.println("长度: " + finalPassword.length());       // 应该输出 64
    System.out.println("校验正确密码: " + Md5Util.verify("123456", finalPassword));   // true

    System.out.println(Md5Util.verify("123456", p1));            // true
    System.out.println(Md5Util.verify("123456", p2));            // true
}
```

```java
        List<UserInfo> users = userMapper.selectList(null);
        for (UserInfo u : users) {
            // 只处理长度不是 64 的（说明还是明文）
            if (u.getPassword() == null || u.getPassword().length() != 64) {
                String encrypted = Md5Util.encrypt(u.getPassword());
                u.setPassword(encrypted);
                userMapper.updateById(u);
                System.out.println("已加密: " + u.getUserName());
            }
        }
    }
}
```

### 11.11 MD5 加盐的安全性说明

| 攻击方式 | MD5 明文 | MD5 加盐 | BCrypt |
| --- | --- | --- | --- |
| 彩虹表反查 | **秒破** | 无效（盐随机） | 无效 |
| 拖库后判断两个用户密码是否相同 | **能判断** | 不能判断 | 不能判断 |
| GPU 暴力破解 | **极快**（MD5 每秒数十亿次） | 快 | **慢**（BCrypt 有意设计得慢） |
| 撞库（用别的网站泄露的密码试） | **危险** | 危险 | 危险 |

**结论**：

- 学习阶段 MD5 加盐**够用**；
- 生产环境建议用 **BCrypt**（Spring Security 自带 `BCryptPasswordEncoder`）或 **Argon2**（更现代）；
- BCrypt 的特点是**计算慢**（可调 cost 因子），有效抵御 GPU 暴力破解；
- BCrypt 的密文格式本身就包含盐和 cost，不需要额外字段。

**改造为 BCrypt 只需三步**（生产环境）：

```java
// 1. 引入 spring-security-crypto 依赖
// 2. 加密：new BCryptPasswordEncoder().encode(rawPassword)
// 3. 校验：new BCryptPasswordEncoder().matches(rawPassword, encodedPassword)
```

```javascript
function renderNavAuth() {
    var $navAuth = $("#navAuth");
    if ($navAuth.length === 0) return;
    if (!isLogin()) return;    // 未登录保持 HTML 里的默认内容
```

**为什么不在 HTML 里直接写死「注销」**：列表页、详情页都允许匿名访问，访客点「注销」会莫名其妙跳到登录页。

### 12.2 详情页「编辑 / 删除」按钮显示条件

```javascript
// ★ 必须同时满足两个条件，缺一不可
var isAuthor = isLogin()
    && String(blogInfo.userId) === String(getLoginUserId());

if (isAuthor) {
    $(".right .content .operating").removeClass("hide");
} else {
    $(".right .content .operating").addClass("hide");
    if (!isLogin()) {
        $(".right .content .login-tip").removeClass("hide");
    }
}
```

**两个条件**：

1. **`isLogin()`**：已登录。少了这个判断会出问题——未登录时 localStorage 里可能残留着 `loginUserId`，只比 userId 的话按钮会显示出来，但点下去必然 401（因为 User-Token 拿不出来）。**按钮的显示条件绝不能比服务的鉴权条件更宽松**。
2. **`userId` 相同**：是本人的博客。两边都转成字符串再比——后端返回 Integer，localStorage 里存的是字符串，直接 `===` 会因类型不同而恒为 false。

### 12.3 XSS 防御：HTML 转义

博客标题和内容都是**用户输入**，直接拼进 HTML 会形成存储型 XSS。

```javascript
function escapeHtml(str) {
    if (str === null || str === undefined) return "";
    return String(str)
        .replace(/&/g, "&amp;")
        .replace(/</g, "&lt;")
        .replace(/>/g, "&gt;")
        .replace(/"/g, "&quot;")
        .replace(/'/g, "&#39;");
}

// 列表页使用
finalHtml += '<div class="blog-title">' + escapeHtml(blogInfo.title) + '</div>';
finalHtml += '<div class="blog-desc">' + escapeHtml(toSummary(blogInfo.content)) + '</div>';
```

**详情页 markdown 渲染的坑**：`editormd.markdownToHTML` 有一个 `htmlDecode` 参数，**不要传值**！源码里 `sanitize = (htmlDecode) ? false : true`，一旦传了值就会关闭 marked 的 HTML 转义，用户就能在博客里注入 `<script>`。保持 `undefined` 才是安全默认。

### 12.4 防连点：submitting 闸门

```javascript
var submitting = false;

function submitBlog() {
    if (submitting) return;      // ★ 闸门
    // ... 校验 ...
    submitting = true;
    $.ajax({
        // ...
        success: function (result) {
            if (result.code == 200 && result.data == true) {
                location.href = "blog_list.html";   // 成功跳走，不复位
                return;
            }
            submitting = false;   // 业务失败要复位，让用户能重试
            alert(result.errMsg || "发表失败");
        },
        error: function (error) {
            submitting = false;   // ★ 网络异常也要复位
            // ...
        }
    });
}
```

## 15. 易错点总结

按类别整理本项目**踩过 / 可能踩**的坑：

### 15.1 JWT 相关

| # | 坑 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 密钥硬编码在 Java 源码里 | 提交到 GitHub 就泄露 | 用 `@Value` 从 yml 注入，yml 加进 `.gitignore` |
| 2 | 密钥长度不够（<256 bit） | `Keys.hmacShaKeyFor` 抛 `WeakKeyException` | 用 `Keys.secretKeyFor(HS256)` 生成 |
| 3 | 把完整 token 打进日志 | 日志泄露 = 账号泄露 | 只打 `e.getMessage()` 或 token 前 8 位 |
| 4 | Payload 里放密码 / 手机号等敏感信息 | Base64 可解码，等于明文 | Payload 只放 id / username |
| 5 | 依赖只加了 `jjwt-api` | 运行时 `ClassNotFoundException` | api / impl / jackson 三件套都要 |
| 6 | 过期时间设置太短（几分钟） | 用户体验差，频繁掉线 | 学习项目 7 天，生产环境按业务权衡 |

### 15.2 拦截器相关

| # | 坑 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 拦截 `/blog/**` 全部路径 | 未登录连首页都打不开 | 只拦写接口（§8.4） |
| 2 | 忘记 `excludePathPatterns("/user/login")` | 登录接口自己被拦，永远登不上 | 登录接口必须排除 |
| 3 | Controller 从 `@RequestParam` 拿 userId | 攻击者改参数就能伪造身份 | 用 `@RequestAttribute` 从 request 域取 |
| 4 | 拦截器里直接 `throw new BlogException` | 异常走不到 `@RestControllerAdvice` | 用 `response.setStatus(401); return false;` |
| 5 | LoginInterceptor 用 `@Autowired` 静态 JwtUtil | 静态方法拿不到 Spring Bean | JwtUtil 用组件，构造器注入 |
| 6 | 忘记 `preHandle` 里 `return true` | 请求默认被拦 | 成功路径必须显式 return true |

### 15.3 加密相关

| # | 坑 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 明文存密码 | 拖库 = 全部泄露 | 必须加密 |
| 2 | 只用 MD5 不加盐 | 彩虹表秒破 | MD5 + 随机盐 |
| 3 | 盐用固定值（比如项目名） | 等价于没加盐 | 每个用户独立随机盐 |
| 4 | 盐和密文分开两个字段存 | 表结构复杂 | 拼在一起存（本项目：前 32 密文 + 后 32 盐） |
| 5 | `encrypt` 里盐拼在密码**前**，`verify` 里拼在**后** | 永远校验失败 | 两边顺序必须一致 |
| 6 | 数据库 `password` 字段长度不够（VARCHAR(32)） | 密文被截断 | 至少 VARCHAR(64)，建议 VARCHAR(128) 留余量 |
| 7 | 生产环境还用 MD5 | GPU 暴力破解风险 | 换 BCrypt / Argon2 |

### 15.4 MyBatis-Plus 相关

| # | 坑 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 忘记 `@TableLogic` | 逻辑删除变成物理删除 | 实体上标注 `@TableLogic(value="0", delval="1")` |
| 2 | 已经 `@TableLogic` 了还手写 `.eq(deleteFlag, 0)` | SQL 里出现两次相同条件 | 让 MP 自动拼，别手写 |
| 3 | `updateById` 时把不想改的字段设为 `""` | 字段被清空 | 设为 `null`，MP 只更新非 null 字段 |
| 4 | `updateById` 返回 0 就报错 | 用户没改内容直接点保存也会报错 | 只有 insert 才判断 `rows != 1` |
| 5 | 忘记 `@TableField(fill=...)` | 自动填充不生效 | 实体字段和 Handler 两边都要配 |
| 6 | `selectOne` 查出多条 | 抛 `TooManyResultsException` | 精确主键查询或加 `LIMIT 1` |

### 15.5 前端相关

| # | 坑 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | `ajaxSetup({ headers: {...} })` 静态写死 token | 登录后 / 登出后 token 不刷新 | 用 `ajaxSend` 每次现读 localStorage |
| 2 | `JSON.parse` 而不是 `JSON.stringify` | 请求体格式错误 | 发送用 `stringify`，接收才用 `parse` |
| 3 | 字段名大小写不一致（`username` vs `userName`） | 后端收到 null，触发 `@NotBlank` | 严格对齐后端 DTO 属性名 |
| 4 | 直接 `$("#content").val()` 读 editor.md 内容 | 拿到的是初始占位文本 | 用 `editor.getMarkdown()` |
| 5 | 用户输入不转义直接拼 HTML | 存储型 XSS | `escapeHtml()` |
| 6 | `editormd.markdownToHTML` 传了 `htmlDecode` | 关闭 sanitize，可注入 script | 保持 `undefined` |
| 7 | `.show()` 覆盖 CSS 的 `display:flex` | 按钮从横排变竖排 | 用 `addClass/removeClass("hide")` |
| 8 | 401 全局处理没做特殊化 | 匿名浏览列表页时被踢到登录页 | 列表页 `getUserInfo` 就地处理 401 |
| 9 | 没有防连点闸门 | 网络慢时点两次发两篇一样的博客 | `submitting` 标志位 |
| 10 | `String(userId) === String(loginUserId)` 写成 `userId === loginUserId` | Integer vs String 恒为 false | 两边都转字符串 |

### 15.6 Spring / 通用

| # | 坑 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | Controller 类上忘记 `@Validated` | 方法参数 `@NotNull` 不生效 | 类上必须挂 |
| 2 | `@RequestBody` 参数忘记 `@Validated` | 对象内字段约束不生效 | 参数前挂 `@Validated` 或 `@Valid` |
| 3 | `Result` 用裸类型 | 编译警告 | 用 `Result<T>` |
| 4 | `ResponseAdvice` 里对 String 直接返回 Result | ClassCastException | 手动 `objectMapper.writeValueAsString` |
| 5 | 异常处理器把 `e.getMessage()` 直接抛给前端 | 泄露 SQL / 表名 | 兜底处理返回统一文案 |
| 6 | 字段注入 `@Autowired` | 难 mock，可能循环依赖 | 构造器注入 |
