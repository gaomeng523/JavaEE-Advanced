# 2026-09-16

## 全项目代码体检（spring-blog-demo / Spring Boot 3.5.7 + MyBatis-Plus 3.5.5 + jjwt 0.11.5）

结论：能编译、能启动，但登录后所有受保护接口实际全部返回 401，链路被两个断点卡死。

### P0 级故障（功能完全不可用）
1. `common/interceptor/LoginInterceptor.java:18` 判断条件取反：
   `if(!StringUtils.isEmpty(userToken) || JwtUtil.parseJwt(userToken) == null)` →
   带上合法 token 反而 401。应为 `isEmpty(...)`。日志 `userToken:null` 大量刷屏即源于此。
2. 前端没有任何一处发送 `User-Token` 请求头：`static/js/common.js` 是空文件（原计划放 `$.ajaxSetup` 全局请求头）；
   `blog_list.html`、`blog_detail.html` 的 `$.ajax` 均未设 headers。登录页已把 token 写入 localStorage，只是没人用。
3. `blog_login.html:48` `data: JSON.parse({...})` 写错，应为 `JSON.stringify({...})`，否则浏览器直接抛 SyntaxError，登录请求发不出去。

### P1 级（逻辑/契约错误）
- `BlogController` 缺类级 `@Validated`，方法参数上的 `@NotNull` 完全失效；`UserController` 同样有 `@NotNull Integer userId/blogid` 但无类级 `@Validated`，同样无效。
- `BlogServiceImpl.getBlogDetal` 未判空 → `BeanTransfer.trans(null)` 触发 `BeanUtils.copyProperties` 抛 IllegalArgumentException；应抛 `BlogException("博客不存在")`。
- `UserController.getAuthorInfo(Integer blogid)` 参数名 `blogid` 与全局 `blogId` 不一致，前端 `location.search` 传 `?blogId=` 会绑不上。
- `UserServiceImpl` 中 `userInfo.getId() < 0` / `blogInfo.getId() < 0` 判空写法错误（自增主键不可能为负），应为 `== null`。
- `UserLoginRequest` 用 `@NotNull` 而非 `@NotBlank`，空字符串能通过校验。
- `ExceptionAdvice` 的 `MethodArgumentNotValidException` 处理器直接 `getFieldError().getDefaultMessage()`，存在 NPE 隐患。

### P2 级（规范/安全/整洁）
- `JwtUtil` 密钥硬编码在源码；`parseJwt` 失败时把完整 token 打进 error 日志；缺 token 时也记 error，噪音大。
- 密码明文比对（`userInfo.getPassword().equals(...)`），未加密存储。
- `getUserInfo(userId)` 用客户端传的 userId 而非 token 中的 id，存在越权风险。
- `UserService` 接口上挂 `@Service`、接口签名挂 `@NotNull`，无意义。
- `Constant` 里 `import BlogMapper` 未使用，`Constant.DELETE` 未使用；`"User-Token"` 硬编码未抽常量。
- `BlogInfoResponse` 残留 `@TableId` 注解（分层污染）；`UserInfoResponse`/`BlogInfoResponse` 通篇多余。
- 注入风格不统一：`BlogController`/`BlogServiceImpl` 构造注入，`UserController`/`UserServiceImpl`/`WebConfig` 字段注入。
- `WebConfig.addInterceptors` 缺 `@Override`；`/blog/**` 是否该登录待定（列表/详情通常应公开）。
- `ResponseAdvice.supports()` 恒 true，会把 404 等错误响应也套成 `code:200`。
- `application.yml` 明文数据库密码；根目录 `spring-blog.log`/`.gz` 未进 `.gitignore`（仅忽略了 `target/`、`.idea`）。

### 修复进度（18:40 复查日志）
- 用户已自行修好 `LoginInterceptor` 的判断条件（截图确认已是 `isEmpty(...)`），`token 不合法` 的 ERROR 不再出现，短路生效。
- 但 18:40:10 那次请求仍 `userToken:null`，且之后没有任何 Controller 日志和 SQL → 请求在 preHandle 就被 401 掉了。
  准确表述（修正之前的说法）：卡点不是"前端"这个角色，而是**「发出去的请求里没有 User-Token 头」**。用户用 Postman 测试时不经过前端，但同样要手动加这个头；两种情况是同一症状的两个独立来源。
  Postman 侧常见原因：用了 Authorization 标签的 Bearer Token（实际发的是 `Authorization: Bearer xxx`，不是 `User-Token`）、头写在 Params、Headers 行未勾选、名字拼写不一致。
- 另发现前端字段名不一致（待修）：`blog_login.html` 登录 body 用的是 `username`，而后端 `UserLoginRequest` 字段是 `userName`；Spring Boot 默认忽略未知属性，会导致该字段为 null 触发校验失败。

### 历史日志已确认修复的问题
- `Unknown column 'username'`：实体字段曾为 `username`，现已改为 `userName`（映射 `user_name`），18:29 登录 SQL 已正常。
- `Request method 'GET' is not supported`：曾把 `getBlogDetail` 写成 PostMapping，现已是 `@GetMapping`。
